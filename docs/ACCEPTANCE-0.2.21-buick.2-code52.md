# BuickPlay 0.2.21-buick.2 / code52 验收版

基于 code51 增加手机恢复后的重连提速与管理页状态通知。应用名 `BuickPlay-debug`，包名 `com.shihab.diplay.hudtest`，版本 `0.2.21-buick.2-debug`；覆盖升级保留设置，不推送远程。

## 改动

- CarPlay host 存活期间接收目标 iPhone 的系统蓝牙 ACL_CONNECTED 事件。如果当前正在等待重试，提前执行原重试任务；重复事件合并，不新建页面或并发连接。
- 校验目标设备、会话所有者、手动停止标记、已连接/设置/重置状态。其他手机或用户主动断开不会触发重连，恢复中的有效控制通道仍受原有防重复重启检查保护。
- 无线普通重试等待依次为 2、4、8、10 秒，最大 10 秒；有线普通重试最大仍为 30 秒，专门的 iAP tunnel 等待与启动失败预算未改。这是失败后的等待时间，不是打开手机开关后的连接时限。
- 管理页在前台时订阅连接 active 状态变化并立即刷新，原有一秒轮询兜底保留；暂停/销毁时取消订阅。
- 新增 `RECONNECT_WAKE source=... remainingWaitMs=...` 与 `HOME_CONNECTION_STATUS active=... resumed=... stateAgeMs=...` 日志。后者是状态改变到文字更新的时间，不等同于屏幕实际呈现或用户观察时间。

## 边界

手机打开蓝牙不保证立即产生 ACL 连接事件，故保留更短的定时兜底；不主动扫描蓝牙、不切换热点、不要求 root。没有事件时，仍可能遇到正在进行的蓝牙连接超时，不能保证恢复后立刻连接。目标 FF-5000 的事件行为仍需实测。

Android 蓝牙广播接收方式参考 [官方广播文档](https://developer.android.com/develop/background-work/background-tasks/broadcasts)。仅监听系统蓝牙 action 并匹配已选择的 iPhone。

## 验收步骤

1. 正常连接，返回连接管理页；主动断开后确认 CarPlay 卡片移除且不会重连。
2. 手动再次连接正常后，保持管理页前台。
3. iPhone Wi-Fi、蓝牙同时关闭约两分钟，再同时打开，记录秒级时间；不点击连接。
4. 记录管理页“已连接”的时间，点击打开 CarPlay 确认直接显示且触摸正常。
5. 分析日志，区分 ACL 事件提前唤醒和 10 秒定时兜底；分别计算等待重试、蓝牙、认证、TCP、首帧和管理页文字更新耗时。

基线：code51 于 19:51:51 手机恢复后等待到 19:52:19.468 才重试，实际重建约 5.2 秒。本版提速效果须复测，尚不能宣称节省了固定秒数。

单卡片整合仍延期，见 [code51 后续记录](ACCEPTANCE-0.2.21-buick.2-code51.md)。

## 先理解日志与配置边界

每次真正创建 CarPlay 控制器会产生独立 UUID 连接轮次；主机窗口的初始化另有 `host_setup` 档案。同一窗口内两轮连接可分别导出。每轮元数据保留原构建/源码版本、启动父ID、进程ID和入队前的墙钟/单调时间。控制器内部重试继续保留 attempt ID；返回或接管仍有效的 CarPlay 会话沿用原轮次，不为记日志重启握手。旧控制器、旧音频解码器的关键清理回调写回原轮次。网络采集按开始时的会话关联，采集期间重连不改写其归属。

这里的连接轮次不是“检测到发动机行程”：没有可验证的厂商 ACC 信号，不能自动判断去程/返程。人工记下出发/到达时间与对应 UUID。跨午夜的长轮次按开始日筛选，选“全部”或具体会话可避免漏选；设备日期无效/跳变时不按猜测日期归类。旧日志迁移时原日期未知，须选“全部”或对应历史会话。

详细原文按7天/128MiB、摘要按14天/4MiB保留，达到任一限制会清理；异常上下文最多8份，每份最近64KiB，至少60秒间隔；网络快照最多3份，每份640Ki字符。保留32MiB空闲空间，单条详细日志最多64Ki字符并显式标记超长截断。旧兼容镜像仍可截断至700字符，完整已采集原文以归档为准。不是无限保留或保证任意负载下保存完整7天。

异步队列最多64条；低存储待保存的会话头最多64份，丢弃最旧头后保留累计计数，空间恢复后写入 `maintenance.txt`。完全不可写时计数只能暂存内存；突然掉电或进程终止仍可能丢失这些计数和未落盘尾部。ZIP 固定各文件截止字节，清单包含 SHA-256、选中/实际字节和局部错误；刷新超时会明确记录，不保证停电级持久化。报告不脱敏、不自动上传，也没有健康摘要页面或结束行程弹窗。

设置备份沿用原 JSON 格式与白名单，包含新增时钟位置/字号、应用音量条开关、自动热点、开机/自动连接、画面及音频设置等。以下内容不会迁移：手动热点 SSID/密码、手机配对/lockdown记录、认证身份与认证材料、系统/ADB/USB权限、设备身份/检测缓存、自定义图标文件。手动热点的频段/信道/安全类型可以迁移，名称/密码需在目标设备另设；正式/调试包须手动导入，配对和授权也须各自完成。它不是完整应用数据备份。

## 无电脑获取完整日志

1. 停车后在诊断页按需采集网络快照。采集不是持续后台任务，不要为采集切换手机网络或重启热点；失败/无本机ADB也应能导出已有日志。
2. 打开“在手机上取得报告”，保持页面开启。手机连接车机可达局域网，扫码或输入地址/配对码；不需要互联网或云端。
3. 分别下载“全部”、具体去程/返程 UUID，以及设备日期可信时的今天/昨天。手机页应显示生成、下载或失败/重试状态；服务器发送完不代表手机已经保存成功。
4. 在 iPhone Safari“文件”中确认 ZIP 已保存，离开车机网络后仍能打开，再转电脑。核对 `manifest.txt` 的文件清单、字节、SHA-256、局部错误和刷新状态，确认两轮原文、异常上下文、网络快照归属。
5. 另测中断/弱网后重试、锁屏、热点地址变化、退出下载页面和服务空闲结束。一个服务同时只允许一份大报告生成/下载，忙碌时503可稍后重试。退出页/Activity销毁会关闭服务，10分钟空闲也会关闭；活动传输的临时 ZIP 在结束/失败后清理，原始档案继续受保留策略保护。

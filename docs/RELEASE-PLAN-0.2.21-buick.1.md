# BuickPlay 0.2.21-buick.1 版本修复与后续优化计划

状态：**已在独立分支整合 main 143f4674 与 BuickPlay 定制，正在调试验收，尚未正式发布**。更新日期：2026-10-22。

### 2026-10-22 最新基线整合

已将 `main` 提交 `143f4674b60b564a16baae5110b3b90fb7277631` 与现有 BuickPlay 品牌、别克图标、详细等待界面、握手持久日志和触摸统计修正整合到 `buickplay/0.2.21-debug`。调试版本 `0.2.21-buick.1-debug`，versionCode `41`，调试包名和本机签名保持不变。

保留上游多指触摸槽位、黑角遮罩与活动会话接管、蓝牙开启后的立即重试、Android 8/9 TCP 失联检测、热点网卡选择、无线音乐时钟和 Bonjour 启动修复。非 BYD 热点设置采用上游新的系统设置权限路径，不覆盖回旧版仅依赖 ADB 的入口。等待页跟随应用主题，保留具体失败原因与操作建议；停止/倒计时单独显示，避免覆盖原因。同一轮有线控制恢复或会话建立后清除旧重试倒计时；接管后台已有主画面时停止连接计时，后续断连不将播放时长计入连接耗时。补齐意大利语和日语等待字符串。

本次整合不代表 B01 手机联网或 B02 全阶段期限已完成，也不将上游其他车型的测试结果当作 FF-5000 验收结果。下方按日期保留原先实施记录。

### 2026-10-21 等待界面先行改动

当前 `kaiyue` 分支先实现 B03 的等待界面展示，尚未合入新基线或发布：显示具体连接阶段、单调时钟计算的总耗时和阶段耗时、当前尝试次数、重试倒计时、最近错误，以及热点频段/信道/车机地址和 CarPlay TCP 接入状态。已完成阶段的耗时按本次尝试保留；手机互联网状态明确显示“未检测”。

本次仅增加观察信息和可滚动的等待界面，不修改连接超时、重试策略或配置页面；进入视频画面或页面退到后台时停止刷新等待计时。B03 仍需实车验收，其余版本修复目标保持规划状态。

等待界面进一步采用横屏分区、竖屏堆叠：突出当前步骤和阶段计时，按车机准备、手机连接与认证、网络接入、CarPlay 握手、显示画面展示进度；已完成步骤显示用时，当前步骤高亮。网络关键状态单列显示，地址及完整诊断信息可展开，返回和重试操作固定在底部。频段、信道在详情中展示，未报告时明确标注未知。

进一步补充连接事件：设备身份交换、iAP2 认证通过、Wi-Fi 参数发送、启动请求发送、TCP 接入、CarPlay 能力交换、配对/验证/认证请求处理、音视频通道协商及主屏视频数据接收。主页面显示距最近有效进展的秒数，频段/信道放入详情；详情按本次尝试的相对时间列出首次观察到的事件。重复事件不重置进展计时，重试清空本轮事件并保留脱敏的最近错误。协议请求“处理中”不等同认证成功。当前无法独立确认 iPhone 的 Wi-Fi 入网/IP 或确认弹窗，也未检测其蜂窝互联网，界面明确说明这些观测边界。

### 2026-10-22 握手日志与触摸统计修正

握手事件在 AirPlay 服务入口显式转发，避免新增接口回调在旧的增量编译代理中落到默认空实现；内部自探测连接不推进手机连接阶段。持久诊断记录同时保留具体 `milestone` 与单调时钟 `atNs`，CarPlay 内设置菜单打开时仍可记录。新增真实服务套接字测试，覆盖重复请求去重及内部探测过滤。

触摸统计按主视频流代次隔离：新流清空旧样本，旧流/副屏不消费新流样本，发送途中发生切换的旧触摸不计入新流。5 秒内未匹配后续视频数据的触摸记为 `touchExpired`，不再统计成数分钟延迟，也不将其夹成一个虚假的延迟值。此期限仅约束诊断样本，未更改 CarPlay 连接期限、重试或视频显示策略。

本版优先解决 FF-5000 后装车机的连接长时间等待、iPhone 接入热点后无法上网，以及音频稳定性问题。后续优化单独列出，不计作本版已承诺交付的功能。

## 已有证据与问题边界

- 用户确认：iPhone 关闭 Wi-Fi 后能上网，连接 BuickPlay 热点后无法上网，无线局域网助理已开启。蜂窝网络本身可用；具体路由、DNS 和热点互联网状态仍需现场定位。
- 用户确认：iPhone 已接入车机热点，系统蓝牙也显示连接时，仍可能长期停在连接页。系统蓝牙连接不能代替 iAP2、AirPlay 和首帧状态。
- 2026-10-14 日志中，两轮蓝牙及认证成功后，各等待首个 AirPlay TCP 30 秒超时，第三轮才出图；不能将全部等待归为认证慢。
- 2026-10-16 两次手动重连分别为 16.819 秒、10.323 秒，其中 TCP 接入至会话建立分别为 11.511 秒、7.071 秒。两次都是用户主动断开，不能计作异常掉线。
- 当前 `FirstTcpWatchdog` 收到首个匹配连接后取消计时，不能覆盖其后的协议停滞。是否需要自行补充修复，以整合后代码复核为准。
- 历史日志出现音频时钟偏差、音轨欠载；也有窗口变化触发重连的手机样本。各项需要车机复测，不能把手机表现直接当作车机结论。
- 车机时钟曾显示 2007 年并发生跳变，耗时统计使用单调时钟。

## 本版必须解决的问题 P0

| 编号 | 问题 | 修复目标 | 验收标准 |
|---|---|---|---|
| B01 | 接入热点后手机无法上网 | 无外网车机热点只承载 CarPlay 本地通信，iPhone 能使用蜂窝互联网；先定位网络选择、路由、DNS 与热点状态识别 | CarPlay 持续运行时，Safari 新网页、在线导航、在线音乐和后台播放均可用；仅开启 Wi-Fi 助理不算通过 |
| B02 | 长时间停在连接页 | 首个 TCP、TCP 后会话建立、会话后首帧分别有启动期限与失败处理 | 任一启动阶段停滞均能结束等待并给出原因；已正常运行的静态画面不因缺少新帧被误断 |
| B03 | 页面无法解释正在等待什么 | 显示蓝牙/iAP2、网络接入、AirPlay 握手、首帧等阶段，提供等待时长、重试次数和失败原因 | 自动重试停止后明确说明，并提供手动重试；错误、缺少权限和等待中有不同提示 |
| B04 | 旧会话和重试可能干扰新连接 | 明确当前连接代次，保留有界退避、取消和清理机制 | 不并发重连；旧回调与旧定时器不能拆掉已恢复的连接；主动断开后停止自动连接；重试不反复重启正常热点 |
| B05 | 音频时钟、欠载和中断恢复异常 | 审查并整合适用的上游通话/导航时钟、麦克风和音乐恢复修复 | 音乐、导航压低音乐、Siri、来电、接听、挂断及返回音乐实测通过；没有持续增长的时钟偏差或反复欠载 |

B01 不能在未采集热点广播前直接归因为信息元素缺失，也不能通过写死手机 IP、网关或 DNS 作为通用修复。若根因涉及固件、驱动或权限，应记录适用范围、可行路径与限制；未解决时不得将本项标为通过。

B02 的阶段期限需结合健康连接样本和上游实现确定，不使用过短超时打断正常的慢握手。网络 keepalive 检测失联与协议阶段期限是两个问题，分别验证。

## 本版优化目标 P1

| 编号 | 目标 | 处理方式 | 验收标准 |
|---|---|---|---|
| B06 | 降低连接耗时波动 | 分段记录配对验证、SETUP、事件通道、RECORD、隧道和首帧，先定位此前约 5 秒无明确进度的间隔 | 分别给出冷连、热连、离开返回的成功率、中位数和 p95；确认根因后再确定速度目标，不承诺未经验证的固定秒数 |
| B07 | 返回桌面、车机页面或倒车画面后保持连接 | 引入适用的上游窗口与画面恢复修复，必要时补充前后台尺寸判断 | 车标、Home、倒车返回分别测试；临时系统栏变化不触发无意义重连，音频与触摸正常；真实旋转、分屏和主动改设置仍正确生效 |

P0 未通过时不以新增功能替代修复。P1 若尚未完成，发布说明逐项写明结果和后续安排，不将其描述为已优化。

## 实施顺序

1. 已锁定 `main` 的 `143f4674` 并整合现有定制；先完成手机和车机对照验收。
2. 优先定位 B01 手机无网和 B02 握手停滞，补齐阶段诊断与启动期限。
3. 验证 B04 连接代次、取消、重试和资源清理，避免恢复过程中引入新的断连。
4. 完成 B05 音频与 B07 窗口恢复回归，再依据分段证据处理 B06 的具体瓶颈。
5. 完成自动检查、实车验收和发布说明，保留上一版 APK 作为对照。

每组改动独立验证。测试时保持手机系统、认证方式和网络拓扑可比，逐项更换变量。

## 发布前验收

停车状态下，使用同一手机、同一固件与明确记录的连接模式执行：

- [ ] 冷连接、热连接各 10 次，记录每次成功与失败阶段。
- [ ] 连接中途打断后重新连接 10 次，确认没有重复任务或旧回调干扰。
- [ ] 手机离开后返回 5 次，确认失联检测、自动恢复和手动停止行为。
- [ ] 车标、Home、倒车返回各 10 次，确认会话、音频和触摸状态。
- [ ] CarPlay 连接期间验证 Safari 新网页、在线导航与在线音乐，另测后台音乐联网。
- [ ] 音乐和导航持续运行至少 1 小时，测试 Siri、来电及挂断恢复。
- [ ] 检查循环连接后的内存、线程、文件描述符和音频欠载，没有持续异常增长。
- [ ] 完成仓库要求的单元测试、lint 和构建检查；需要界面改动时补充对应布局验证。
- [ ] 验证 release 的签名、包名、旧设置迁移和认证方式；签名密钥与认证材料不写入本文。
- [ ] 将实际测试版本、结果、限制与未完成项写入发布说明，未实测的场景明确标注。

## 后续独立优化清单

以下为后续候选任务，不预先指定发布版本；实车数据可以调整优先级。

| 编号 | 优化方向 | 启动条件与预期收益 |
|---|---|---|
| F01 | 板载 MFi 认证 | 应用 UID 下验证总线、芯片版本、证书与签名，处理原厂服务竞争；主要减少对 APK 软件身份的依赖，不预期直接解决 Wi-Fi 或握手等待 |
| F02 | 2.4GHz 蓝牙共存与 5GHz 热点能力 | 核实实际频段、蓝牙引导交接与其他音频 profile；5GHz 需先证明车机 AP 能力，再做同条件对照，不以芯片名称推断支持 |
| F03 | 手机返回后的快速重试 | 在可靠的选定手机或唤醒事件到达时缩短退避等待，保留去抖、取消与单次连接限制 |
| F04 | Android 8.1 TCP 失联检测 | 核对旧系统文件描述符生命周期和 keepalive 参数能力，避免空闲误断，并记录断连检测时延 |
| F05 | FF-5000 视频和资源调优 | 对 H.264、直接输出、流畅视频及 MTK 调优逐项 A/B；以解码、触摸延迟、内存和清晰度决定预设，保持软件 HEVC 默认关闭 |
| F06 | 日志降载与 Bonjour 清理 | 按需启用详细协议跟踪，减少字符串和磁盘开销；拆分约 4 秒清理耗时，保证无旧监听、端口或回调残留后再优化 |
| F07 | ACC 唤醒、时钟与有线后备 | 区分冷启动和 quickboot，验证热点/蓝牙准备顺序；核对系统对时；比较 BuickPlay 有线与 PhoneLink 有线的实际耗时 |
| F08 | 方向盘按键、小灯联动与底部时钟 | 先验证厂商事件和权限，再接入现有控制；底部时钟作为安卓叠层单独设计，不承诺移动 iPhone 原生状态栏 |

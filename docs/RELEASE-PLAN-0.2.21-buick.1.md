重复 TCP、协议请求及详细 milestone 日志不续期。首帧确认仅接受当前主屏视频流，仪表副屏、镜像窗口及已替换流/解码器的延迟诊断回调不算主屏成功；流更换时绑定新的渲染观察者。同一主屏在 RECORD 前已实际渲染时，保留其 token 证明并在会话激活后确认；换流后旧证明失效。首次主屏渲染后取消启动期限，不以静态画面或后台低帧率判定超时。内部自探测、其他监听器及过期代次不推进当前启动状态；阶段迁移、主动停止和旧计时任务受取消标记保护。超时复用现有有界重试预算，新增“会话建立超时”和“首帧显示超时”提示，网络地址族切换仍只用于首个 TCP 超时。

现有详细日志保持不变；额外记录启动阶段、期限、单调时间、实际已等待时长及最后观察到的 milestone。协议事件仅用于记录最后进展，不作为认证成功或画面已显示的证据。本次不修改 B01 的热点网络配置，也不修改有线启动期限。

### 2026-10-22 握手日志与触摸统计修正

握手事件在 AirPlay 服务入口显式转发，避免新增接口回调在旧的增量编译代理中落到默认空实现；内部自探测连接不推进手机连接阶段。持久诊断记录同时保留具体 `milestone` 与单调时钟 `atNs`，CarPlay 内设置菜单打开时仍可记录。新增真实服务套接字测试，覆盖重复请求去重及内部探测过滤。

触摸统计按主视频流代次隔离：新流清空旧样本，旧流/副屏不消费新流样本，发送途中发生切换的旧触摸不计入新流。5 秒内未匹配后续视频数据的触摸记为 `touchExpired`，不再统计成数分钟延迟，也不将其夹成一个虚假的延迟值。此期限仅约束诊断样本，未更改 CarPlay 连接期限、重试或视频显示策略。

本版优先解决 FF-5000 后装车机的连接长时间等待、iPhone 接入热点后无法上网，以及音频稳定性问题。后续优化单独列出，不计作本版已承诺交付的功能。

- 2026-10-14 日志中，两轮蓝牙及认证成功后，各等待首个 AirPlay TCP 30 秒超时，第三轮才出图；不能将全部等待归为认证慢。

## 本版必须解决的问题 P0

| 编号 | 问题 | 修复目标 | 验收标准 |
|---|---|---|---|
| B01 | 接入热点后手机无法上网 | 无外网车机热点只承载 CarPlay 本地通信，iPhone 能使用蜂窝互联网；先定位网络选择、路由、DNS 与热点状态识别 | CarPlay 持续运行时，Safari 新网页、在线导航、在线音乐和后台播放均可用；仅开启 Wi-Fi 助理不算通过 |
| B02 | 长时间停在连接页 | 首个 TCP、TCP 后会话建立、会话后首帧分别有启动期限与失败处理 | 任一启动阶段停滞均能结束等待并给出原因；已正常运行的静态画面不因缺少新帧被误断 |
| B03 | 页面无法解释正在等待什么 | 显示蓝牙/iAP2、网络接入、AirPlay 握手、首帧等阶段，提供等待时长、重试次数和失败原因 | 自动重试停止后明确说明，并提供手动重试；错误、缺少权限和等待中有不同提示 |
| B04 | 旧会话和重试可能干扰新连接 | 明确当前连接代次，保留有界退避、取消和清理机制 | 不并发重连；旧回调与旧定时器不能拆掉已恢复的连接；主动断开后停止自动连接；重试不反复重启正常热点 |
| B05 | 音频时钟、欠载和中断恢复异常 | 审查并整合适用的上游通话/导航时钟、麦克风和音乐恢复修复 | 音乐、导航压低音乐、Siri、来电、接听、挂断及返回音乐实测通过；没有持续增长的时钟偏差或反复欠载 |

B01 不能在未采集热点广播前直接归因为信息元素缺失，也不能通过写死手机 IP、网关或 DNS 作为通用修复。若根因涉及固件、驱动或权限，应记录适用范围、可行路径与限制；未解决时不得将本项标为通过。

B02 的阶段期限需结合健康连接样本和上游实现确定，不使用过短超时打断正常的慢握手。网络 keepalive 检测失联与协议阶段期限是两个问题，分别验证。

## 本版优化目标 P1

| 编号 | 目标 | 处理方式 | 验收标准 |
|---|---|---|---|

## 2026-10-26 已确认的下一版本优化项（尚未实现）

以已安装的 code46 正式版为起点，下一版本号尚未确定。首次连接、重复连接与异常恢复的速度和可靠性仍为最高优先级。以下为用户已确认需求，仅记录计划，不代表当前 APK 已包含。

### N01 自动详细日志保留与行程归档

问题证据：2026-10-25 去程、返程均使用导航，但约 4MB 的循环日志只留下返程 17:16–17:57，去程及返程初始连接已被覆盖。

- 自动持久保存详细日志，按会话分文件、按行程归档；去程与返程分别保留。应用重新打开或车机重启不主动清空上一轮记录，无需用户每次手动保存。
- 单独保留低频行程/连接摘要：版本、启动原因、连接各阶段耗时、重试、主动/异常断开原因、音视频统计与异常。详细日志轮转不应覆盖仍在保留期内的摘要。
- 初始建议：摘要保留14天并设置独立容量上限；详细日志保留7天或总计128MB，达到任一上限清理最旧文件。实施前结合车机可用存储确定具体参数，摘要上限、异常份数及空间不足行为尚待设计；不承诺无限或无条件保留7天。
- 连接超时、非主动断开及音频异常的现场记录单独保留最近若干份，尽量复用已有详细日志及前后文；重复异常需合并/限频，不能无限复制。
- 按用户要求保留详细原始信息，不脱敏。明确标记截断、丢弃、清理及采集失败，不能静默遗漏或把容量受限说成完整记录。
- 每次启动/会话使用可关联编号，记录设备墙钟、时区和单调时钟；标明日期异常/时间跳变。单调时间只用于同一次启动内的耗时，不能跨重启直接相减，也不能把错误设备日期当作真实日期。
- 支持按今天、昨天或最近几天导出摘要、详细日志、异常记录与相关网络快照；日期不可信时应提供按启动/会话选择方式，不依赖错误日期误归档。
- 后台有界批量写入，兼顾正常退出刷新和异常断电时可能丢失的尾部范围；控制存储、队列及CPU开销，不影响连接、导航和播放。

验收：同日去程/返程跨应用退出及车机重启后均可导出；连接开始、失败、重试和首帧可关联；覆盖容量/保留期清理、时间跳变及异常中断；对比启用前后的连接耗时与音视频表现。单次出现音频欠载计数不直接等同可听卡顿。

### N02 保留手动热点网络采集，与自动日志关联

- 保留“设置 → 诊断 → 采集热点网络诊断”入口，不以自动详细日志替代。
- 自动详细日志记录过程；手动快照补充故障当时的热点、接口、路由、DNS、网络共享和系统状态，尤其用于“已连热点但手机无网”等问题。
- 快照记录采集ID、开始/结束时间及对应启动、会话、连接尝试编号；与 N01 同一导出流程打包，保留命令状态、耗时、权限不足、失败和截断信息。
- 正常行程无需点击；网络问题仍存在时先采集，再重连或重启。采集不能自动重启热点、修改网络或改变连接状态。
- 不把完整网络采集变成持续后台任务；保持有界、按需执行，避免无线ADB与CarPlay竞争。既有快照保留最近三份的规则是否调整，应在实现 N01 时明确，不将其误述为已经扩大。

验收：一份诊断包可关联故障前后详细过程与现场快照；无本机ADB/权限不足时保留基础信息并说明缺失项；采集失败不影响已有日志导出。

### N03 区分连接管理与 CarPlay 任务窗口

最近任务标题分别为“BuickPlay · 连接管理”和“BuickPlay · CarPlay”；调试版保留 -debug 标识，桌面正式应用名称不变。先验证两个任务窗口的标题设置路径，再实车验证桌面/最近任务显示，不将此项描述为合并窗口或连接提速。

### N04 音量条统一样式与步长

- 导航和媒体均采用普通黑色半透明样式，取消橙色样式。
- 导航音量使用导航图标，媒体音量使用扬声器图标，不加小字说明。
- 保留独立音量，步长统一为1；目标是导航正在播报时调整导航音量，其余时间调整媒体音量。

### N13 手机获取诊断报告：当前代码完整性检查

现有链路：设置 → 诊断 → “在手机上取得报告”，启动局域网 HTTP 服务，显示二维码及手动输入地址/配对码；手机浏览器进入下载页，下载 `diplay-report.txt`。下载页须保持开启；服务有10分钟空闲关闭机制，退出页面/Activity销毁会停止服务。手机必须能访问车机所在局域网，车机热点开启且手机接入时可在无外网条件下传输，不依赖电脑或云端。

报告生成与“保存诊断报告”共用 diagnosticReportText：包含构建与设备信息、当前配置/显示/启动/按键诊断、进程退出/崩溃信息、已保存的热点网络快照，以及仍在保留范围内的所有 SessionLogFile.REPORT_NAMES（最多8份）会话日志。下载不会自动执行新的完整网络采集，也不能恢复已被轮转删除的日志。

已有服务端测试覆盖：UTF-8、下载响应头、Content-Length、大报告逐字节一致性、生成失败返回500、错误地址/方法、地址排序、并发空闲连接及服务关闭。真实红米浏览器/iPhone Safari下载到本机文件并转电脑尚待实测，不能把回环网络测试等同现场全链路验收。

已发现并列入改进：

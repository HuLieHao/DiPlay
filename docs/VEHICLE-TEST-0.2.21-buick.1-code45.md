## 操作顺序

1. 停车后连接车机 ADB，先确认当前版本和保存必要的旧日志，再覆盖安装 code45。不要卸载调试版，不清数据，保留已有配对、热点和主题配置。原正式版包名不同，不用卸载。
2. 打开“BuickPlay 调试版”，确认版本 code45、热点信息和原有设置；iPhone 保持 Wi-Fi、蓝牙开启。测试时先关闭设置菜单。
3. 在无持续 ADB 日志/截图/文件传输的情况下连接。记录点击时间、首帧时间，以及是否出现 iPhone 授权弹窗。连接后播放音乐至少 3 分钟并确认联网。
4. 连续做 5 次正常断开/重新连接，分别记下用户主动操作和结果。每次等断开/恢复完成，不连续点击重连。
5. 做一次应用进程冷启动后连接，以及一次手机离开覆盖范围后返回。真正首次配对需要另安排清配对实验，本轮不擅自清除。
6. 额外做一次打开设置菜单期间的断开/恢复，验证日志能保留，同时确认旧回调未改变新会话状态。此项与前面的性能基线分开记录。
7. 完成一组测试后暂停播放，再到设置中的诊断保存报告并导出。整个测试过程本地记录，导出期间不计入正常速度/音频验收。
8. 最后检查7000端口归属、当前发布的发现服务和真实热点配置。只读查询；厂商提权仍先验证只读入口，不能改挂载、权限、系统文件、服务启停或热点参数。

## 分析与判定

| 关注项 | 本次读取什么 | 后续决定 |
|---|---|---|
| /info 冷响应 | handleMs、encodeTraceMs、encryptMs、writeMs、flushMs | 加密慢再评估预热/实现；写入慢转查网络背压；不先盲改图标 |
| 认证提前发送 | authFlushMs、认证成功响应节点 | 避免最后一次空 flush 掩盖实际认证 flush 等待 |
| 重连清理 | Bonjour teardown elapsedMs、controller 清理时长 | 与 code44 约4秒对比；验证没有残留发布、端口或线程问题 |
| 首个断开 | airplay-first-close、source、reason、cause、atNs、sessionId、controllerGeneration | 定位 control/event/video/iAP/service/owner 谁先触发关闭；这只是本地首个关闭调用，不自动等于物理根因 |
| 重复配对 | pair-setup / pair-verify、当前接收端身份和配对记录 | 区分手机行为、身份不一致和多个实例竞争 |
| 接入与首帧长尾 | StartSession→TCP→session→VIDEO_RECEIVED→首帧 | 区分网络关联、协议等待与解码，不用总耗时猜原因 |

`write`/`flush` 返回不证明手机已收到；毫秒值为单调计时，日志显示时间可能不同。第一条关闭记录只记录赢得关闭原子门的调用，级联关闭不覆盖它；没有系统 errno 的异常不能凭空推断 errno。

通过标准：无旧回调误关新连接，关键诊断可导出，原有连接/联网/音频能力不退化，清理耗时相较原版有可重复改善。5次为现场筛查，随后扩展至少10次；不能以单次最快结果或3分钟音乐流畅代表长期可靠性。

日志仍受既有容量、轮转及后台队列上限约束，不能承诺无限保留。每完成一组及时导出；所有报告保持现有不脱敏策略。

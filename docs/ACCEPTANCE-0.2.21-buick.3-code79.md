## 改动与依据

11月1日实车中，code71 可发现 /dev/i2c-2:0x10 的芯片，但在 iAP2 证书长度或内容读取阶段出现 errno=6。临时探针带有选择寄存器后5ms等待，已读取908字节证书、128字节签名并本地验签通过；尚不能据此证明iPhone接受该证书。

本版仅在 FF_5000/FF-5000、Linux I2C 后端、路径 /dev/i2c-2 时启用 BoardMfiTransport：单字节寄存器选择事务成功返回后等待5ms。扫描、协议版本、分块证书、签名状态/结果、错误码读取共用该适配层。保持选择与读取间的STOP语义。其他机型、总线、CH341、软件及远程认证不启用等待。

等待中断会恢复线程中断标志并终止本次操作；保留原有有限重试及连接期限。新增失败阶段、地址、寄存器、读取长度、失败次数、操作重试次数和耗时日志；传输错误沿用原异常信息（包含errno），不记录挑战/证书/签名正文。成功读取证书、签名时仅记录字节数。没有添加软件回退、证书缓存、原厂服务停止或系统权限改动。

## 用户实车验收

1. 覆盖安装调试包，保留数据。设置 → 连接 → MFi证书与签名目标 → 板载MFi芯片（实验性）。
2. 不插USB，手动连接iPhone；观察画面并播放音乐30秒。失败时记录大致时间、保留日志，不连续反复操作。
3. 首次成功后手动断开/重连3次，再补车机冷启动。
4. 核对日志 registerSettleMs=5、certificate_read、signature_read，以及iAP2认证、AirPlay认证和首帧；发现芯片成功不代表完整认证成功。
5. 需要恢复日常使用时手动选“本地离线”并重新连接。
